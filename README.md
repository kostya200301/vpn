# VPN Server: Xray VLESS + REALITY и MTProto-прокси для Telegram

Собственный VPN-сервер на VPS, который ставится одной командой. Внутри:

- **VPN**: [Xray-core](https://github.com/XTLS/Xray-core) с протоколом **VLESS + REALITY + XTLS Vision**. Для внешнего наблюдателя трафик выглядит как обычный HTTPS к крупному сайту (по умолчанию `www.microsoft.com`). Клиентское приложение — **HAPP** на Windows, macOS, Android и iOS.
- **Telegram**: отдельный **MTProto-прокси** [mtg](https://github.com/9seconds/mtg) с маскировкой FakeTLS. Работает независимо от VPN и добавляется прямо в Telegram одной ссылкой.
- **Управление**: Docker Compose, скрипты `install.sh` и `manage.sh`. Секреты генерируются автоматически, JSON руками править не нужно.

## 1. Архитектура и почему она такая

```
 Устройства (HAPP)                          VPS (Docker)
 ┌───────────────┐   TCP 443, VLESS+REALITY  ┌──────────────────────────┐
 │ iPhone        │ ────────────────────────▶ │ vpn-xray  (Xray-core)    │ ──▶ Интернет
 │ Android       │                           │  • свой UUID и shortId   │
 │ Windows/macOS │                           │    у каждого устройства  │
 └───────────────┘                           │  • чужие подключения →   │
                                             │    прозрачно на          │
 Telegram                                    │    www.microsoft.com     │
 ┌───────────────┐   TCP 8443, MTProto       ├──────────────────────────┤
 │ Telegram      │ ────────────────────────▶ │ vpn-mtproto (mtg)        │ ──▶ Серверы Telegram
 └───────────────┘   FakeTLS                 └──────────────────────────┘
```

| Решение | Почему |
|---|---|
| **VLESS + REALITY + Vision** | Не нужен ни домен, ни TLS-сертификат. Сервер выдаёт себя за реальный сайт: при проверке без ключа отвечает его настоящим сертификатом. Vision убирает характерный признак «TLS внутри TLS». Это актуальный рекомендуемый режим Xray-core. |
| **Без Nginx** | REALITY сам слушает порт 443 и сам маскируется. Nginx понадобился бы только для подписок по HTTPS, а это лишняя поверхность атаки и необходимость в домене и сертификате. |
| **mtg v2** вместо официального `telegrammessenger/proxy` | Официальный образ давно не обновляется. mtg v2 поддерживается, умеет FakeTLS (секрет `ee…`) и работает с одним маленьким конфигом. |
| **Один источник правды: `data/clients.json`** | Конфиг Xray генерируется из списка клиентов и шаблона. Каждое изменение сначала проверяется самим Xray (`xray run -test`) и только потом применяется: сломанная конфигурация на сервер не попадёт. |
| **Docker Compose профили** | Telegram-прокси включается и выключается одной командой, не затрагивая VPN. |

**Закреплённые версии** (заданы в `docker-compose.yml`, проверены на дату создания проекта, ноябрь 2026):

| Компонент | Образ |
|---|---|
| Xray-core | `ghcr.io/xtls/xray-core:26.10.31` — официальный образ XTLS, стабильный релиз от 31.10.2026 |
| mtg | `nineseconds/mtg:2.2.8` — официальный образ автора mtg, последняя номерная версия |

### Совместимость с HAPP: что проверено, а что нет

- HAPP официально поддерживает **VLESS (Reality)** и импорт ссылок `vless://` из **буфера обмена, по QR-коду и по deep-link** ([документация HAPP](https://www.happ.su/main/faq/adding-configuration-subscription)).
- Ссылка формируется по общему стандарту обмена ссылками Xray: `security=reality`, `pbk`, `sid`, `sni`, `fp`, `flow=xtls-rprx-vision`, `type=tcp`. На странице HAPP перечня этих параметров нет, но приложение построено на Xray-core и понимает этот стандарт. **Перед тем как раздавать ссылки, проверьте одно устройство.**
- **Подписки (subscription URL) в проекте сознательно не реализованы.** Для них нужен HTTPS-сервер, домен и сертификат, то есть Nginx и Certbot. Каждому устройству хватает одной ссылки или QR. Если со временем понадобится, подписку можно добавить отдельным сервисом.

## 2. Требования к VPS

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu 22.04 / 24.04, Debian 12 / 13 | Ubuntu 24.04 LTS |
| Архитектура | x86_64 (amd64) или aarch64 (arm64) | — |
| Виртуализация | KVM / VMware / Xen (OpenVZ и LXC — с ограничениями) | KVM |
| CPU / RAM | 1 vCPU / 512 МБ | 1 vCPU / 1 ГБ |
| Диск | 1.5 ГБ свободно | 5 ГБ+ |
| Сеть | Публичный IPv4, открытые входящие TCP 443 и 8443 | — |
| Доступ | root или sudo по SSH | — |

Домен **не нужен**. Если у провайдера VPS есть свой firewall в веб-панели (Hetzner Cloud Firewall, Security Groups и т. п.), разрешите там входящие **TCP 443** и **TCP 8443**, а также порт SSH.

## 3. Установка

### 3.1. Подключитесь к VPS

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

### 3.2. Клонируйте репозиторий и запустите установку

```bash
apt-get update && apt-get install -y git      # если git ещё нет
git clone https://github.com/ВАШ_ЛОГИН/vpn-server.git
cd vpn-server
chmod +x install.sh
sudo ./install.sh
```

Мастер задаст несколько вопросов. Везде можно просто нажать **Enter**:

| Вопрос | По умолчанию | Комментарий |
|---|---|---|
| Публичный IP или домен сервера | определяется автоматически | попадает в ссылки подключения |
| Порт VPN | `443` | лучше не менять: 443 выглядит как обычный HTTPS |
| Сайт для маскировки REALITY | `www.microsoft.com` | проверяется поддержка TLS 1.3 и HTTP/2 |
| Метка сервера | `DE` | имя подключения в HAPP будет `DE-phone` |
| Включить Telegram-прокси | да | |
| Порт Telegram Proxy | `8443` | |
| Домен FakeTLS для Telegram | как у REALITY | |
| Настроить UFW | да | SSH-порт разрешается **до** включения firewall |
| Включить TCP BBR | да | ускоряет передачу на каналах с потерями |
| Имя первого устройства | `phone` | |

Установка без вопросов, со значениями по умолчанию:

```bash
sudo ./install.sh -y
```

### 3.3. Что делает установщик

1. Проверяет ОС.
2. Проверяет ресурсы: архитектуру, RAM, диск, тип виртуализации.
3. Ставит системные пакеты (`curl jq qrencode openssl ufw …`).
4. Ставит Docker Engine и Compose из официального репозитория Docker (если их нет), включает автозапуск, синхронизирует время по NTP.
5. Создаёт каталоги `data/` и `backups/` с правами `700`.
6. Создаёт `.env` с правами `600` через мастер.
7. Скачивает закреплённые версии образов.
8. Генерирует ключи x25519 (`xray x25519` с контрольной сверкой пары), секрет MTProto (`mtg generate-secret --hex`), UUID и shortId первого устройства.
9. Собирает конфиги Xray и mtg и проверяет конфиг Xray командой `xray run -test`.
10. Проверяет, свободны ли порты и не совпадают ли они с SSH. Настраивает UFW и BBR.
11. Запускает контейнеры и ждёт, пока они стабилизируются.
12. Запускает health-check и выводит **ссылку и QR-код для HAPP** и **ссылку Telegram Proxy**.

### 3.4. Повторный запуск

`sudo ./install.sh` можно запускать сколько угодно раз. Существующие ключи, секреты и клиенты **не меняются**: скрипт только доустанавливает недостающее и перезапускает сервисы.

Изменить настройки (адрес, порты, сайт маскировки):

```bash
sudo ./install.sh --reconfigure
```

> Если сменился адрес, порт или SNI, ссылки на устройствах нужно обновить: `sudo ./manage.sh show-config <имя>`.

Другие флаги: `--skip-firewall` (не трогать UFW), `--force` (неподдерживаемая ОС, на свой риск).

## 4. Подключение устройств через HAPP

**Одна ссылка — одно устройство.** Под каждое устройство заведите отдельное подключение (`add-client`): тогда доступ любого из них можно отозвать, не трогая остальные.

```bash
sudo ./manage.sh add-client iphone
```

Команда выведет ссылку `vless://…` и QR-код прямо в терминале.

> Если QR в терминале «поплыл», уменьшите шрифт или растяните окно. Другой вариант — сохранить картинку: `sudo ./manage.sh show-config iphone --png` создаст `data/export/iphone.png`; скачайте её через `scp` и **удалите** с сервера.

### Где взять HAPP

Только из официальных источников. Ссылки на все платформы есть на сайте [happ.su](https://www.happ.su/main/readme). iOS: [App Store — «Happ - Proxy Utility»](https://apps.apple.com/app/id6504287215). Android: Google Play или APK с официального сайта. Windows и macOS: установщики на официальном сайте.

### iOS (iPhone, iPad)

1. Установите **Happ - Proxy Utility** из App Store.
2. На сервере выполните `sudo ./manage.sh show-config iphone`, чтобы на экране компьютера появился QR-код.
3. В HAPP нажмите **«+»** и выберите сканирование QR-кода. Наведите камеру на QR в терминале.
   - Другой способ: перешлите ссылку `vless://…` себе (в «Избранное» Telegram), скопируйте её на iPhone, в HAPP нажмите **«+»** → вставка из буфера обмена.
4. Нажмите на появившийся сервер `DE-iphone` и кнопку подключения. Разрешите добавить VPN-конфигурацию (iOS спросит один раз).

### Android

1. Установите **Happ** из Google Play (или APK с официального сайта).
2. **«+»** → сканировать QR-код, либо скопируйте ссылку и выберите вставку из буфера.
3. Подключитесь и разрешите создание VPN-соединения.

### Windows

1. Скачайте и установите HAPP для Windows с официального сайта.
2. Скопируйте ссылку `vless://…` из терминала SSH: выделите её мышью, в большинстве терминалов она скопируется сразу.
3. В HAPP нажмите **«+»** → добавить из буфера обмена.
4. Подключитесь. Чтобы через VPN шёл трафик всех программ, а не только браузера, включите в настройках HAPP режим VPN/TUN (запуск от имени администратора), если он есть в вашей версии.

### macOS

1. Установите HAPP для macOS (с официального сайта или из Mac App Store).
2. Скопируйте ссылку из терминала, в HAPP нажмите **«+»** → вставить из буфера обмена.
3. Подключитесь и разрешите добавление VPN-конфигурации в системных настройках.

### Проверка

Откройте в браузере любой сервис, который показывает IP (например, `https://ifconfig.me`). Должен отображаться IP вашего VPS в Германии.

## 5. Telegram Proxy

После установки ссылка уже выведена в терминал. Получить её ещё раз:

```bash
sudo ./manage.sh telegram-link
```

Будут показаны две ссылки и QR-код:

```
tg://proxy?server=203.0.113.10&port=8443&secret=ee…
https://t.me/proxy?server=203.0.113.10&port=8443&secret=ee…
```

**Как добавить:**

- **Телефон**: откройте ссылку `https://t.me/proxy?...` (или отсканируйте QR камерой). Telegram предложит **«Подключить прокси»**.
- **Компьютер**: вставьте ссылку в любой чат (хотя бы «Избранное») и нажмите на неё. Либо вручную: *Настройки → Продвинутые настройки → Тип соединения → Использовать собственный прокси → MTProto*, затем сервер, порт и секрет.

**Управление:**

```bash
sudo ./manage.sh telegram-rotate              # новый секрет: старая ссылка перестанет работать у всех
sudo ./manage.sh telegram-rotate www.apple.com  # новый секрет с другим доменом FakeTLS
sudo ./manage.sh telegram-status              # состояние контейнера
sudo ./manage.sh logs mtproto                 # логи
sudo ./manage.sh telegram-disable             # выключить (VPN продолжит работать)
sudo ./manage.sh telegram-enable              # включить
```

Прокси работает независимо от VPN: его можно выключать, перезапускать и менять ему секрет, не затрагивая подключения HAPP.

## 6. Управление устройствами

```bash
sudo ./manage.sh add-client win-laptop     # новое устройство (ссылка + QR)
sudo ./manage.sh list-clients              # список (UUID замаскированы; --full — полностью)
sudo ./manage.sh show-config win-laptop    # ещё раз показать ссылку и QR
sudo ./manage.sh show-config               # общие параметры сервера + все активные ссылки
sudo ./manage.sh disable-client win-laptop # временно отключить (например, устройство потеряно)
sudo ./manage.sh enable-client win-laptop  # вернуть доступ (прежняя ссылка снова заработает)
sudo ./manage.sh remove-client win-laptop  # удалить навсегда
```

- Имена: латиница, цифры, `-` и `_`, до 32 символов.
- У каждого устройства свои **UUID** и **shortId**. Отключение или удаление убирает их из конфигурации, и доступ пропадает сразу после автоматического перезапуска Xray. При перезапуске остальные устройства переподключаются примерно за 1–2 секунды.
- Последнее активное устройство удалить или отключить нельзя: Xray без клиентов не запустится. Сначала добавьте новое.
- Если ключ сервера мог утечь (например, вместе с бэкапом), выполните `sudo ./manage.sh rotate-reality-keys`. После этого **все** устройства нужно добавить в HAPP заново.

## 7. Все команды manage.sh

`sudo ./manage.sh` без аргументов открывает **интерактивное меню**.

| Команда | Действие |
|---|---|
| `install [--reconfigure]` | установка или перенастройка |
| `start` / `stop` / `restart` | запуск / остановка / перезапуск всех сервисов |
| `status` | состояние контейнеров, CPU, RAM, трафик |
| `logs [xray\|mtproto] [N]` | логи, последние N строк и далее в реальном времени (Ctrl+C — выход) |
| `update [-y] [--no-git]` | безопасное обновление |
| `backup` / `restore [файл]` | резервная копия / восстановление |
| `add-client <имя>` | новое устройство |
| `remove-client <имя> [-y]` | удалить устройство |
| `disable-client` / `enable-client <имя>` | отключить / включить устройство |
| `list-clients [--full]` | список устройств |
| `show-config [<имя>] [--png] [--no-qr]` | параметры подключения, ссылка, QR |
| `telegram-link` | ссылка Telegram Proxy |
| `telegram-rotate [домен]` | новый секрет Telegram |
| `telegram-enable` / `telegram-disable` / `telegram-status` | управление прокси |

| `firewall [apply\|status]` | правила UFW |
| `rotate-reality-keys` | новые ключи REALITY |
| `uninstall [--purge] [-y]` | удаление |

## 8. Обновление

```bash
cd ~/vpn-server
sudo ./manage.sh update
```

Как проходит обновление:

1. Создаётся **резервная копия**.
2. Если каталог — git-репозиторий без локальных правок, показываются новые коммиты и делается `git pull --ff-only` (с подтверждением).
3. Скачиваются образы тех версий, что закреплены в `docker-compose.yml`.
4. Конфиги собираются заново и проверяются **новой** версией Xray.
5. Контейнеры перезапускаются (обрыв около 2 секунд).
6. Запускается health-check.
7. **Если что-то пошло не так**, код откатывается к прежнему коммиту, а сервисы перезапускаются на старой версии. В выводе будет команда восстановления из бэкапа.

**Как обновить версию Xray или mtg.** Измените тег образа в `docker-compose.yml` (и закоммитьте в свой репозиторий) или переопределите его на сервере в `.env`:

```bash
echo 'XRAY_IMAGE=ghcr.io/xtls/xray-core:НОВАЯ_ВЕРСИЯ' | sudo tee -a .env
sudo ./manage.sh update --no-git
```

Список версий: [Xray-core releases](https://github.com/XTLS/Xray-core/releases), [mtg на Docker Hub](https://hub.docker.com/r/nineseconds/mtg/tags). Не используйте теги `latest`, `stable` и `master`.

Обновление ОС (иногда нужно и ядро, например при уязвимостях):

```bash
sudo apt-get update && sudo apt-get upgrade -y && sudo reboot
```

После перезагрузки контейнеры поднимутся сами (`restart: unless-stopped`, Docker в автозапуске).

## 9. Резервные копии

```bash
sudo ./manage.sh backup
# -> backups/vpn-backup-20261109-153000.tar.gz   (права 600)
```

В архиве лежат `.env` (ключи REALITY, секрет Telegram, настройки) и `data/` (клиенты и конфиги). Хранятся последние `BACKUP_KEEP` копий (по умолчанию 10). Копия создаётся и автоматически: перед обновлением, восстановлением и удалением.

**Скопируйте бэкап к себе** (в архиве секреты, храните его так же бережно, как пароль):

```bash
# на своём компьютере:
scp root@IP_СЕРВЕРА:~/vpn-server/backups/vpn-backup-*.tar.gz .
```

**Восстановление** (в том числе на новом VPS):

```bash
# 1) на новом сервере:
git clone https://github.com/ВАШ_ЛОГИН/vpn-server.git && cd vpn-server
sudo ./install.sh -y                         # поставит Docker и всё нужное

# 2) на своём компьютере — загрузить архив:
scp vpn-backup-….tar.gz root@НОВЫЙ_IP:~/vpn-server/backups/

# 3) на новом сервере:
sudo ./manage.sh restore backups/vpn-backup-….tar.gz
```

При переезде на сервер с **другим IP** выполните затем `sudo ./install.sh --reconfigure`, укажите новый адрес и разошлите обновлённые ссылки (`show-config <имя>`, `telegram-link`). Ключи и UUID останутся прежними.

Восстановление само проверяет архив: распаковываются только `.env` и `data/`, другие пути отклоняются.

## 10. Безопасность

| Мера | Реализация |
|---|---|
| Секреты не попадают в Git | `.env`, `data/`, `backups/` в `.gitignore`. В репозитории только `.env.example` без значений |
| Секреты генерируются автоматически | x25519 — `xray x25519`, MTProto — `mtg generate-secret`, UUID — ядро Linux, shortId — `openssl rand` |
| Права на файлы | `.env`, `clients.json`, бэкапы — `600`; `data/`, `backups/` — `700`; конфиги — `640` с группой контейнера |
| Контейнеры без root | Xray — UID 65532, mtg — UID 65534 |
| Изоляция контейнеров | `read_only`, `cap_drop: ALL`, `no-new-privileges`, конфиги монтируются только для чтения |
| Логи без секретов | access-лог Xray выключен (`access: none`), уровень `warning`; ротация логов Docker 3×10 МБ; скрипты не печатают секреты в сообщениях об ошибках; `list-clients` маскирует UUID |
| Ограничение исходящего трафика VPN | клиентам VPN запрещён доступ к частным сетям сервера (`geoip:private`) и BitTorrent. В Германии за торренты через ваш IP приходят претензии от правообладателей (Abmahnung) |
| Firewall | UFW: запрещены все входящие, кроме SSH и портов VPN. **SSH-порт определяется (`sshd -T`, `$SSH_CONNECTION`, `ss`) и разрешается до включения UFW** |
| Проверка портов | установщик не запустится, если порт занят чужим процессом или совпадает с SSH |
| Защита от битой конфигурации | любое изменение проверяется `xray run -test` до применения |
| Автозапуск | Docker `enable`, у контейнеров `restart: unless-stopped` |
| Закреплённые версии | точные теги образов; `latest` не используется |

**Важно про Docker и UFW.** Docker публикует порты через собственные правила iptables, в обход UFW. Поэтому наружу открыты ровно те порты, что указаны в `docker-compose.yml` (443 и 8443), и закрыть их через `ufw deny` не получится. Чтобы закрыть сервис, выключите его (`telegram-disable`) или уберите порт из compose.

**Рекомендации сверх проекта:** входите по SSH-ключу и отключите вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config`). Можно установить `fail2ban` и `unattended-upgrades`.

## 11. Диагностика и решение проблем

Начинайте всегда с этого:

```bash
sudo ./manage.sh health
```

Проверяется: Docker и его автозапуск, состояние и перезапуски контейнеров, прослушивание портов, корректность конфига (`xray run -test`), **реальное TLS-рукопожатие REALITY** через порт 443, приём соединений MTProto, ошибки в логах за 15 минут (выводится только их количество), синхронизация времени, диск и память, UFW, BBR.

| Симптом | Что проверить |
|---|---|
| HAPP подключается, но сайты не открываются | `sudo ./manage.sh health`. Время на телефоне и сервере: REALITY чувствителен к расхождению часов, на устройстве должно стоять автоматическое время. Пересоздайте ссылку: `show-config <имя>` |
| Не подключается совсем | Открыт ли порт у провайдера VPS (firewall в веб-панели)? С компьютера: `nc -vz IP 443`. Не отключено ли устройство (`list-clients`)? |
| Перестало работать в сети провайдера/страны | Смените сайт маскировки: `sudo ./install.sh --reconfigure`, введите другой домен (например `www.apple.com`, `dl.google.com`, `www.samsung.com`), затем обновите ссылки на устройствах |
| Контейнер постоянно перезапускается | `sudo ./manage.sh logs xray 200` |
| `Порт 443 занят` при установке | Другой веб-сервер: `sudo ss -ltnp 'sport = :443'`. Остановите его или выберите другой порт через `--reconfigure` |
| Telegram «подключение…» без конца | `sudo ./manage.sh telegram-status`, `logs mtproto`. Порт 8443 открыт у провайдера? Попробуйте `telegram-rotate` с другим доменом |
| После перезагрузки не работает | `systemctl status docker`, `sudo ./manage.sh status`, `sudo ./manage.sh start` |
| Потерял SSH после включения UFW | Через веб-консоль VPS: `ufw allow <ваш_порт_ssh>/tcp` или `ufw disable` |

Полезное:

```bash
sudo ./manage.sh status                 # контейнеры и ресурсы
sudo ./manage.sh logs xray 300          # 300 строк логов Xray
sudo docker compose ps                  # то же средствами Docker
sudo ./manage.sh firewall status        # правила UFW
```

## 12. Полное удаление

```bash
cd ~/vpn-server
sudo ./manage.sh uninstall            # контейнеры, правила UFW для VPN, настройка BBR (бэкап сохранится)
sudo ./manage.sh uninstall --purge    # + образы, ключи, клиенты, бэкапы (НЕОБРАТИМО, спросит DELETE)
cd .. && sudo rm -rf vpn-server       # удалить сам проект
```

SSH-правила UFW и сам UFW остаются включёнными, чтобы сервер не остался без защиты. Docker тоже не удаляется. Если он больше не нужен:

```bash
sudo apt-get purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo rm -rf /var/lib/docker /var/lib/containerd /etc/apt/sources.list.d/docker.list /etc/apt/keyrings/docker.asc
```

```
vpn-server/
├── docker-compose.yml            # сервисы xray и mtproto, закреплённые версии, hardening
├── .env.example                  # шаблон настроек (без секретов)
├── .gitignore                    # исключает .env, data/, backups/
├── install.sh                    # установка (12 шагов, идемпотентная)
├── manage.sh                     # управление: меню и команды
├── lib/
│   └── common.sh                 # общие функции: .env, клиенты, генерация и проверка конфигов
├── config/                       # ШАБЛОНЫ (в Git)
│   ├── xray/config.template.json
│   └── mtproto/config.template.toml
├── scripts/
│   ├── generate-keys.sh          # x25519, секрет MTProto (только недостающие / ротация)
│   ├── add-client.sh  remove-client.sh  toggle-client.sh  list-clients.sh  show-config.sh
│   ├── telegram.sh               # link / rotate / enable / disable / status
│   ├── backup.sh  restore.sh  update.sh  uninstall.sh
│   ├── health-check.sh           # диагностика
│   └── firewall.sh               # UFW с защитой SSH
├── tests/
│   ├── lint.sh                   # статические проверки
│   └── e2e.sh                    # сквозной тест с реальным VPN-соединением
├── .github/workflows/ci.yml      # lint + e2e в GitHub Actions
├── data/                         # СГЕНЕРИРОВАННОЕ (не в Git): clients.json, xray/, mtproto/, export/
└── backups/                      # резервные копии (не в Git)
```

Вручную ничего править не нужно. Если всё же хочется изменить шаблон (например, правила маршрутизации в `config/xray/config.template.json`), после правки выполните `sudo ./install.sh`: он соберёт конфигурацию, проверит её через `xray run -test` и перезапустит сервисы. Ключи и клиенты при этом не изменятся.

## 14. Тестирование

- `bash tests/lint.sh` проверяет синтаксис всех скриптов, `shellcheck`, `docker compose config`, закреплённые версии образов, шаблоны и то, что секреты игнорируются Git.
- `sudo bash tests/e2e.sh` — сквозной тест **на чистом тестовом сервере** (не на рабочем: он занимает порты 443/8443). Ставит проект, проверяет повторный запуск (ключи и UUID не меняются), добавление, отключение и удаление клиентов, **реальное VLESS+REALITY-соединение** (клиент Xray → сервер → `generate_204` через туннель), отказ в доступе отключённому клиенту, ссылку и порт Telegram, смену секрета, backup/restore, подъём контейнеров после перезапуска Docker, non-root/read-only контейнеры и отсутствие секретов в Git и логах.
- В GitHub Actions оба теста запускаются автоматически при каждом push (`.github/workflows/ci.yml`). Смотрите вкладку **Actions** в репозитории.
